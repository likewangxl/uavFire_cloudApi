# S2.1 处置事件状态机修正补丁报告

日期：2026-07-02

## 修正内容

- 新增 `OperationIncidentEvent.CONTINUE_RESPONSE`，补齐 `RECHECKING --CONTINUE_RESPONSE--> RESPONDING` 复测未解除后继续处置回路。
- 新增 `OperationIncidentStatus.ABORTED`，并在枚举 Javadoc 标注“评审报告 20260702 批准新增”。
- 拆分误报与中止语义：
  - `MARK_FALSE_ALARM`：仅 `CANDIDATE`、`CONFIRMED` 可进入 `FALSE_ALARM`。
  - `ABORT`：`CONFIRMED`、`DISPATCHING`、`RESPONDING`、`RECHECKING` 进入 `ABORTED`。
  - `CANDIDATE` 不再允许 `ABORT`。
  - `ABORTED --ARCHIVE--> ARCHIVED`。
- `/api/operations/incidents/{id}/abort` 保持路径但语义改为进入 `ABORTED`，服务层要求中止原因非空。
- 新增 `POST /api/operations/incidents/{id}/mark-false-alarm`，挂 `@Idempotent("operation.incident.mark-false-alarm")`，审计日志记录操作人与原因。
- 同步更新 `fc100_init.sql` 与迁移 SQL 的 `operation_incident.status` 字段注释。
