# S6 巡检闭环实施报告 - 2026-07-02

## 范围

- 后端 `fc100/event` 增加候选火情确认、驳回、复测结果接口：
  - `POST /api/fire/events/{id}/confirm`
  - `POST /api/fire/events/{id}/reject`
  - `POST /api/fire/events/{id}/recheck-result`
- 前端 operation workbench 接入真实 `CANDIDATE` 火情流，确认/误报/复测提交改为真实接口调用。
- 未修改 `FireMissionStatus`、`IncidentTransitionTable`、S1 释放策略、S4 锁与队列、S5 规则语义。
- 未改 `cloud-sdk`、`rcplus-msdk-agent`、`ai-service`。

## 后端实现

- AI/巡检上报不再直接生成 `WAITING_REVIEW` 灭火任务；`confidence >= 0.10` 的新火情保存为 `fire_event.status=CANDIDATE`、`confirmed_status=PENDING`。
- `confirm` 流程：
  - 写 `confirmed_status=CONFIRMED`、记录操作人。
  - 复用已有活跃 `operation_incident`；没有则调用 `OperationIncidentService.create` 创建。
  - 仅当 `geo_quality/locationQuality=PRECISE` 且无活跃草稿时创建 `fc100_fire_mission`，状态为 `CREATED`，并回填 `incident_id`。
  - 非 `PRECISE` 不生成任务草稿，incident 回填 `recommended_recheck=1` 和“需复测或人工标注坐标”原因。
- `reject` 流程：
  - 写 `confirmed_status=REJECTED`。
  - 若已关联 `CANDIDATE/CONFIRMED` incident，则联动 `markFalseAlarm`。
- 复测：
  - 新增 `fc100.thermal.saturation-temp-c`，默认 `540`。
  - 对饱和场景，不能仅凭绝对温度下降判定解除；需要无明火、温度下降、热源面积同步下降。
  - `recheck-result` 会推动 incident `RECHECKING -> RESOLVED` 或 `RECHECKING -> RESPONDING`。

## auto-created mission 现状与处理

原 `FireEventServiceImpl.create` 在 AI 上报时存在 `auto-created mission ... from fire event` 的自动建 `WAITING_REVIEW` 任务路径，这与“人工确认前不得生成可派发 FC100 灭火任务”的 S6 红线冲突。

本次处理为：AI 上报阶段只产出候选火情，不再返回或插入自动任务；任务草稿创建移动到人工确认后的 `confirm` 流程，且只创建 `CREATED` 草稿。`CREATED` 不是审核/下发状态，后续派发仍受 S5 R01/R08 等预检规则兜底。

## 前端实现

- 工作台加载 `operation_incident` 的同时拉取 `fire_event.status=CANDIDATE`，映射为候选列表项。
- `确认火情` 调用 `confirm`，成功后刷新并选中新 incident。
- `标记误报` 对候选火情调用 `reject`。
- 详情面板展示坐标质量徽标、置信度、热成像饱和警示、非 PRECISE 草稿提示。
- 新增最小复测录入表单：温度、热源面积、明火、建议。
- `operation-policy.mjs` 增加坐标质量、饱和警示和草稿提示策略函数与测试。
