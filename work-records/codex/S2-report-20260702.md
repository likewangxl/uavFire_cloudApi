## Design Notes

- Package choice: `com.yx.uavfire.fc100.operation`, because S2 reuses fc100 `ApiResult`, `Fc100BusinessException`, `@Idempotent`, fire-event entities, and FC100 mission linkage.
- Audit choice: new `operation_incident_log` table, mirroring `fc100_mission_log` style without mixing incident status history into mission logs.
- `location_quality` maps to existing `fire_event.geo_quality`; no duplicate column added.
- `source_type` maps to existing `fire_event.source`; no duplicate column added.
- `confidence` already exists on `fire_event`; no duplicate column added.
- Abort maps active incidents to `FALSE_ALARM`, because the required S2 status enum does not include `ABORTED` or `CANCELLED`; `close` archives `RESOLVED` or `FALSE_ALARM`.
- Dispatch does only S2 work: validates `DELIVERY_PRIMARY`, calls no-op `PreflightGate`, then transitions `CONFIRMED -> DISPATCHING -> RESPONDING`.
- S4 resource lock and command execution logic were intentionally not implemented; only schema/entities/mappers were added.
