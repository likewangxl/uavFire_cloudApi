# T3 Report - 帧探测事件驱动测温

日期：2026-07-06

## 设计说明

### 帧探测回调接口

- 在 `ThermalFrameProbe` 增加 `ThermalHotspotCandidateListener` fun interface。
- `ThermalFrameProbe` 构造注入 `hotspotCandidateListener`，默认 `NO_OP`，保持既有构造兼容。
- `maybeDetectHotspot` 检出候选 ROI 后更新 `latestHotspot`，随后同步调用 listener；listener 只通知候选，不在解码线程执行测温。
- `DjiMsdkStreamBinder` 和 `RealMsdkStreamProvider` 透传 listener。
- `AppServices` 使用 `ThermalHotspotTriggerBridge` 把 probe 回调转发到 `ThermalHotspotMonitor.onFrameHotspotCandidate(activeDroneSn)`。

### 去抖与互斥

- `ThermalHotspotMonitor` 新增 `onFrameHotspotCandidate(droneSn): Job`，将回调切入 `monitorScope` 协程执行。
- 帧触发路径复用与 `pollOnce` 相同前置条件：`sessionState == RUNNING` 且 `thermalMonitoringEnabled == true`。
- `probeMutex` 作为测温流程互斥锁，周期轮询和帧触发共享，同一时刻只允许一个测温流程进入。
- 帧触发路径使用 `DEFAULT_FRAME_TRIGGER_DEBOUNCE_MS = 2_000`：一次帧触发测温流程完成后，2s 内新回调直接忽略。
- 周期轮询保留，仍按 `DEFAULT_PROBE_INTERVAL_MS = 2_000` 兜底执行。

### urgent 命令通道

- `AgentCommandResponse` 增加 nullable `urgent: Boolean?`，backend 缺字段时为 `null`。
- `CommandPollingCoordinator` 增加 `pollLegacyDualStreamUrgentOnly`：
  - `false`：普通 5s 轮询保持旧行为，执行 pending legacy dual-stream 命令。
  - `true`：urgent 轮询只执行 `urgent == true` 的 legacy dual-stream 命令；`null/false` 不 ack，留给普通轮询。
- `LegacyCommandDeduplicator` 记录 in-flight legacy commandId。
- `AppServices` 普通 dual-stream poller 与 urgent MSDK poller 共用同一个 deduplicator，防止同一 legacy 命令被两个 poller 并发执行。
- urgent poller 现在同时拉取 MSDK 命令和 urgent legacy dual-stream 命令。
