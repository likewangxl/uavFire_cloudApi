## 锁并发保证方案

选择数据库唯一约束作为最终并发裁决，而不是依赖应用层先查后插。

原因：
- 同一资源锁必须跨线程、跨实例成立，应用锁或先查后插无法覆盖多 JVM 场景。
- MySQL 没有原生 partial unique index，因此使用生成列模拟“仅 ACTIVE 参与唯一约束”。
- 历史 `RELEASED` / `EXPIRED` lease 记录继续保留，满足审计需要。

迁移 SQL：
- `backend/sql/migrations/2026-07-02-operation-lease-command-queue-s4.sql`

同步初始化 SQL：
- `backend/uavfire/sql/fc100_init.sql`

关键唯一键：
- `UNI_OPERATION_LEASE_ACTIVE_RESOURCE(active_resource_sn)`：同一 `resource_sn` 只能有一个 ACTIVE lease。
- `UNI_OPERATION_LEASE_ACTIVE_DELIVERY_OWNER(active_delivery_owner_id)`：同一 incident owner 只能有一个 ACTIVE `DELIVERY_PRIMARY` lease。

## 队列驱动方式

使用现有 Spring `@Scheduled` 模式，未引入新框架。

调度入口：
- `CommandQueueScheduler.tickOperationQueue()`

每轮执行：
- `resourceLeaseService.expireStale()`
- `commandQueueService.markSendTimeouts()`
- `commandQueueService.markAckTimeouts()`
- `commandQueueService.dispatchDueCommands()`

状态机：
- `PENDING -> SENDING -> WAIT_ACK -> ACKED`
- 失败/超时：`FAILED` / `TIMEOUT`
- 超过 `fc100.command-queue.max-retries` 后进入 `DEAD`
- `TIMEOUT` / `DEAD` 写入 `待人工接管` 信息，可通过 commands 查询接口回放。

配置默认值：
- `fc100.command-queue.max-retries: 3`
- `fc100.command-queue.send-timeout: 10s`
- `fc100.command-queue.ack-timeout: 30s`
- `fc100.command-queue.retry-backoff: 5s`
- `fc100.command-queue.dispatch-batch-size: 20`

补充覆盖：
- 并发抢锁：两线程同时 acquire 同一 SN，仅一个成功。
- 心跳过期：`expireStale` 后可重新 acquire。
- 幂等 enqueue：同 `idempotency_key` 返回已有指令，不重复 insert。
- 重试与 DEAD：模拟执行器失败，`retry_count` 到上限后进入 `DEAD`。
- 释放红线：`MANUAL_CONFIRM` 未确认仍被 `PayloadReleasePolicyService` 拒绝，adapter/queue 不发送。
- assign-delivery：锁占用时返回 `RESOURCE_CONFLICT`，assignment 不落库。
