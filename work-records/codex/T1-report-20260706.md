# T1 RC 端热区探测提速与告警去阻塞报告

## 改动清单

- `rcplus-msdk-agent/app/src/main/java/com/yinxin/uavfir/api/ThermalHotspotMonitor.kt`
  - `DEFAULT_PROBE_INTERVAL_MS` 从 `10_000L` 调整为 `2_000L`。
  - `THERMAL_SNAPSHOT_REMEASURE_ATTEMPTS` 从 `4` 调整为 `1`。
  - 温度达标后先调用 `client.recordThermalHotspotEvent`；热快照 URL 缺失时以 `null` 上报，不再跳过告警事件。
  - 热快照上传重试和一次重测移动到上报后的异步流程；成功后继续触发可见光确认，失败只记录告警日志，不影响已上报热事件。

- `rcplus-msdk-agent/app/src/main/java/com/yinxin/uavfir/stream/DjiMsdkStreamBinder.kt`
  - `locateAndMeasureThermalHotspotC` 主路径改为只测量帧候选热区和 `seedRegion`。
  - 帧候选经聚类去重后最多取 3 个；`seedRegion` 存在且不重复时追加测量。
  - 无帧候选且无 `seedRegion` 时直接返回 `null`，不再进入 9 区粗扫、局部细扫或全屏 CENTER 兜底。
  - 保留 `>=120.0C` fast-confirm 提前返回。
  - CENTER 兜底仅保留在 `seedRegion != null` 且候选测量无结果的场景。
  - `coarseThermalScanRegions()` / `localThermalScanRegions()` 保留在文件中，但主路径不再调用。

- `rcplus-msdk-agent/app/src/test/java/com/yinxin/uavfir/api/ThermalHotspotMonitorTest.kt`
  - 新增默认 2 秒探测周期断言。
  - 将“热快照缺失跳过事件”更新为“热快照缺失仍上报事件且 `thermalImageUrl == null`”。
  - 新增/更新异步快照重试与一次重测断言。

- `rcplus-msdk-agent/app/src/test/java/com/yinxin/uavfir/stream/DjiMsdkStreamBinderHotspotSelectionTest.kt`
  - 新增帧候选最多 3 个断言。
  - 新增无候选且无 seed 时返回 `null`、零次测温调用断言。
  - 新增 fast-confirm 只测到首个强热点即返回的断言。

## 后端契约核查

- 已检查 `AgentBackendClient.recordThermalHotspotEvent`、`DualStreamController.event`、`DualStreamEventDTO`、`DualStreamServiceImpl.acceptEvent/applySingleStreamReview`。
- 后端 Controller/DTO/Service 接收链路不强制 `thermalImageUrl` 非空；空值可以进入事件列表。
- 后端当前 review 语义会将缺失热图的热确认事件标为 `THERMAL_IMAGE_MISSING`，未发现 HTTP/DTO 级拒绝。
- 结论：backend 零改动。
