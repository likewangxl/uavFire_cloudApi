## 实现内容

1. 详情操作栏新增 `分配 FC100`、`分配巡检机`。
   - `CONFIRMED` 状态可见。
   - 弹窗录入设备 SN、角色、备注。
   - 角色支持 `DELIVERY_PRIMARY` / `DELIVERY_BACKUP`、`MONITOR_PRIMARY` / `MONITOR_RECHECK`。
   - 最近使用 SN 写入 localStorage。
   - 成功后刷新 incident 列表与详情；资源冲突等后端 message 用 toast 暴露。

2. 预检接入真实前端调用。
   - 新增 `operationComplianceApi.runPreflight()` 调 `POST /api/compliance/preflight-checks`。
   - `CompliancePanel` 展示总体结论和 R01-R15 规则行。
   - `BLOCK` 项红色高亮。
   - dispatch 被预检阻断时，从错误响应 `data` 提取同结构结果并渲染。

3. 任务生成入口改为状态说明。
   - 未发现独立 incident 生成任务接口；后端路径为确认火情时自动创建草稿任务。
   - 因此隐藏旧的灰态 `生成灭火任务` 按钮。
   - 详情中显示：
     - 已有 mission：`任务 {mission_no}（{状态}）`
     - 无 mission 且 PRECISE：`确认时自动生成`
     - 非 PRECISE：`坐标非 PRECISE，暂不生成任务`

4. 合规录入最小界面。
   - `CompliancePanel` 新增折叠区 `录入合规记录`。
   - 支持飞行申请、起飞确认、落地报告、四类资质档案录入。
   - 资质类型：`CLUSTER_FLIGHT_PERMIT`、`AIRDROP_APPROVAL`、`AIRWORTHINESS`、`JOINT_OPERATION_AGREEMENT`。
   - 提交调用 `record-flight-application`、`record-takeoff-confirmation`、`record-landing-report`、`qualifications`。

5. 详情数据补全。
   - incident 详情缺少坐标质量、置信度、热成像温度时，按 `fireEventId` 调 `GET /api/fire/events/{eventId}` 回填。
   - 同步补中心坐标、误差半径、mission 信息的空值 fallback。

6. Mock 模式补齐。
   - `operationComplianceApi` 支持 `VITE_OPERATION_MOCK` / `uavfire_operation_mock`。
   - Mock 预检会让 R02/R10/R15 随录入记录变化；设备在线、电量、能量预算等 mock 相关项仍保持 BLOCK，便于演示预期说明。

## 策略测试

新增/调整断言：

- `ASSIGN_DELIVERY`、`ASSIGN_MONITOR` 在 `CONFIRMED` 可见可用。
- `RUN_PREFLIGHT` 在 `CONFIRMED` 可见可用。
- `GENERATE_MISSION` 因无独立后端接口而隐藏。
- `missionPresentation()` 覆盖已有任务、PRECISE 无任务、非 PRECISE 无任务三态。

## 验收剧本

1. 打开工作台，选择 `CONFIRMED` 事件。
2. 点击 `分配 FC100`，输入 SN，例如 `FC100-DELIVERY-01`，角色选择 `DELIVERY_PRIMARY` 并提交。
3. 详情刷新后资源分配出现 `DELIVERY_PRIMARY / ACTIVE`；`派发` 按钮按 `hasActiveDeliveryPrimary` 策略亮起。
4. 点击 `运行预检`，查看 `CompliancePanel` 中 R01-R15 结果；无合规记录时 R02/R15 为 BLOCK。
5. 展开 `录入合规记录`，录入飞行申请，并依次录入四类资质档案。
6. 重新点击 `运行预检`，R02/R15 的 BLOCK 应减少或转 PASS。
7. 若设备在线、电量、DeliveryHub、能量预算等 mock/外部状态仍 BLOCK，属于当前环境预期。
8. 点击 `派发`；若后端预检仍阻断，弹窗报错，同时阻断明细继续显示在 `CompliancePanel`。
