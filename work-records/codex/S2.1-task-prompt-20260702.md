## 问题 1：缺少"复测未解除 → 继续处置"回路

主方案 §5.3 要求：M4T 复测显示火情未解除时，事件回到"继续处置"。当前 IncidentTransitionTable 中 RECHECKING 只能 RESOLVE / ABORT。

修正：新增事件 `CONTINUE_RESPONSE`，迁移 `RECHECKING --CONTINUE_RESPONSE--> RESPONDING`。

## 问题 2：中止与误报语义混淆

当前 ABORT 从任何状态都进 FALSE_ALARM。真火情处置中途被中止不是"误报"，会污染误报统计与事后复盘。

修正：
- OperationIncidentStatus 新增 `ABORTED`（这是对主方案 8 态的经评审批准的扩展，请在枚举 javadoc 注明"评审报告 20260702 批准新增"）。
- 事件拆分：
  - `MARK_FALSE_ALARM`：仅 CANDIDATE、CONFIRMED → FALSE_ALARM（尚未实际处置，确属误判）。
  - `ABORT`：CONFIRMED、DISPATCHING、RESPONDING、RECHECKING → ABORTED（中止处置，必须携带原因）。
  - CANDIDATE 不再有 ABORT（候选阶段只有确认或标记误报）。
  - `ABORTED --ARCHIVE--> ARCHIVED`。
- Controller：/abort 语义改为进入 ABORTED；新增 POST /api/operations/incidents/{id}/mark-false-alarm（挂 @Idempotent，记录操作人与原因）。
- 同步更新 fc100_init.sql / 迁移 SQL 中 status 字段注释。
