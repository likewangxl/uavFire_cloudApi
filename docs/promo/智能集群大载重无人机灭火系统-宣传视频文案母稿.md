# 智能集群大载重无人机灭火系统宣传文案母稿

版本：2026-06-15

用途：用于制作系统宣传视频脚本、旁白文案、PPT 解说词和项目推介材料。

## 一、系统定位

智能集群大载重无人机灭火系统，是面向森林防火、火情侦察、应急扑救和灾后复盘的一体化无人机作战平台。

系统以大疆开放平台能力为基础，结合 Matrice 4T、RC Plus 2、FlyCart 100 等设备形态，构建从“火情感知、实时传输、AI 识别、指挥决策、航线调度、灭火作业、数据复盘”到“战术优化”的全流程闭环。它不是单一的无人机巡检工具，而是把无人机、视频流、AI 算法、航线任务、火情事件、指挥驾驶舱和作业记录统一到一个业务系统中，服务森林消防的真实作战流程。

系统面向的核心问题是：火点发现不够早、现场态势不够清、扑救路径不够快、作业过程难追踪、灾后复盘缺数据。通过无人机空中视角、热成像/可见光感知、AI 火情识别、RC Plus 端执行层、ZLMediaKit 媒体中枢和后端任务调度能力，系统帮助指挥人员把原本分散的“看、判、飞、投、记”整合为连续动作。

## 二、建设背景

森林火灾具有突发性强、蔓延速度快、地形环境复杂、人员进入风险高等特点。传统巡护和扑救方式在偏远林区、山地林区、夜间火情和大风天气中容易受到限制：

1. 人工巡查覆盖范围有限，初期火点发现晚。
2. 地面人员和消防车辆进入困难，错过小火早扑窗口。
3. 指挥中心缺少实时影像、热源信息、飞行状态和作业过程数据。
4. 多架无人机、多类任务和多种载荷之间缺乏统一调度。
5. 灭火、巡检、复盘的数据链路割裂，难以形成可持续优化的战术体系。

本系统围绕这些痛点，将无人机从“单机巡检设备”提升为“空地协同作战单元”，让火情发现更早、态势判断更准、任务下发更快、作业过程更可控。

## 三、系统总体架构

系统采用“设备层、媒体与通信层、平台服务层、业务应用层”的整体架构。

设备层包括 M4T 侦察无人机、RC Plus 2 遥控器、FC100 大载重无人机、RTK 定位设备、机载载荷与灭火投放装置。设备负责火场感知、飞行执行、载荷投放、位置采集和状态上报。

媒体与通信层以 ZLMediaKit、RTMP、RTSP、WebRTC 和 MQTT 为核心，负责把前线视频、遥测、任务状态和事件消息稳定传回系统。RC Plus 端的 MSDK Agent 可以向媒体服务推送直播流，并把设备状态、航线进度和执行结果回传给后端。

平台服务层包括 Java 后端、DualStream 双流运行时、航线任务服务、火情事件服务、AI 服务和数据存储。该层负责统一设备接入、任务调度、火情识别、事件聚合、航线生成、状态管理和业务数据沉淀。

业务应用层包括 Web 前端、指挥驾驶舱、航线规划页面、火情事件列表、直播监控面板和任务管理界面。指挥人员可以在统一界面中查看实时画面、设备状态、火点告警、航线任务和处置进展。

当前系统的主链路可以概括为：

```text
M4T / RC Plus 2
  -> rcplus-msdk-agent
  -> ZLMediaKit RTMP / WebRTC
  -> backend DualStream runtime + ai-service
  -> 指挥驾驶舱 + 火情事件工作流
```

## 四、核心特点

### 1. 空中感知与实时回传

系统通过无人机搭载可见光、变焦和热成像能力，对林区、山地、火场边界和重点风险区域进行空中巡查。前端驾驶舱可以查看无人机直播画面，后端可以获取无人机状态、任务进度和火情识别事件。

与传统固定监控或人工巡护相比，无人机具备机动性强、覆盖范围广、视角灵活的优势。对偏远林区、山脊、沟谷、夜间热点和人员难以抵达区域，无人机能够快速抵近观察，为指挥中心提供第一手影像。

### 2. AI 火情识别与事件触发

ai-service 支持从 ZLMediaKit RTSP、本地视频或图片读取输入，进行可见光火焰/烟雾识别、热成像热点分析和融合判断。识别结果可以形成 dual-stream detection event，并在达到阈值时生成 FireEvent，触发后续消防任务流。

系统不是只把视频“播出来”，而是把视频流接入算法链路，自动识别疑似火点、风险等级和现场截图，使指挥人员可以更快从海量画面中发现重点目标。

当前 AI 能力定位为 PoC 到实战验证阶段，可根据现场数据继续训练和调参。系统已预留 YOLO 权重接入、连续视频消费、截图留存、事件回传和风险分级能力，为后续模型优化提供基础。

### 3. 指挥驾驶舱统一态势

前端指挥驾驶舱面向火场指挥人员，整合实时直播、设备状态、火情告警、任务状态和态势信息。指挥人员不需要在多个系统之间切换，就可以看到“哪里有火情、哪架无人机在线、画面是否正常、任务是否执行、事件是否已生成”。

驾驶舱的价值在于把复杂底层链路收敛成可操作的指挥界面：现场画面用于观察，火情事件用于判断，航线任务用于处置，状态反馈用于闭环。

### 4. RC Plus 端 MSDK Agent 执行层

系统在 RC Plus 2 上建设了 rcplus-msdk-agent，用于替代部分 Pilot 2 数据面能力。Agent 可以进行 MSDK 初始化、设备会话管理、运行状态上报、命令轮询、RTMP 推流、OSD/HMS 上报和航线执行。

这一设计让系统不完全依赖官方 Pilot 2 的交互路径，而是将直播、遥测、任务执行和事件回传纳入自研业务链路。对森林消防场景而言，这意味着系统可以围绕“巡检、识别、下发、执行、反馈”进行更深度的业务定制。

### 5. 航线规划与任务执行

系统支持将后端生成的 KMZ 航线下发到 RC Plus 端 Agent，由 Agent 通过 DJI MSDK v5 的航线任务能力在 M4T 上执行。任务过程中的状态变化、进度、航点动作和执行结果可以回传后端。

航线任务不只是“飞一条线”，还可以承载巡检高度、速度、云台俯仰、拍照、悬停、云台旋转等动作配置。对森林消防来说，这使系统可以围绕重点林区巡检、火点复核、火线边界侦察、投放前确认等场景生成标准化作业流程。

### 6. 火点定位与精度演进

系统已经设计火点精确坐标链路：基于无人机位置、姿态、云台角度、识别框、DEM 高程和多帧观测数据，逐步从单帧粗定位演进到多视角交会定位。目标是让火点位置不仅“看起来在地图上”，而是具备可解释、可复核、可验收的误差半径。

该能力对后续自动生成观测航线、灭火投放航线和火场复盘具有重要价值。它可以帮助系统从“发现疑似火点”进一步走向“确认火点坐标、评估定位精度、生成后续处置任务”。

### 7. 大载重灭火作业衔接

系统的业务目标面向 FC100 等大载重无人机灭火作业。侦察无人机负责发现火情、确认坐标、传回态势；大载重无人机负责携带灭火载荷进入作业区域，执行精准投放或协同扑救任务。

这种“侦察无人机 + 大载重作业无人机 + 指挥平台”的组合，可以把无人机从单纯看火扩展到参与早期扑救，适用于人员难以进入、车辆难以抵达、火源仍处于初期可控阶段的场景。

### 8. 全流程数据沉淀与复盘

系统能够记录火情事件、识别截图、任务状态、航线进度、设备遥测和操作过程。灾后复盘时，可以回看火情从发现、判断、派发、执行到处置的完整链路，为战术优化、人员培训、责任追溯和装备评估提供数据支撑。

这使系统不只是一次性的应急工具，也可以成为长期森林防火能力建设的数据底座。

## 五、系统优势

### 1. 发现更早

无人机可以快速抵达重点区域进行巡检，AI 识别可以在连续视频中自动筛选疑似火点。相比完全依赖人工盯屏和地面巡查，系统更适合大范围、长时间、高风险区域的火情发现。

### 2. 判断更准

系统将可见光画面、热成像热点、无人机位置、航线状态、火情截图和历史事件统一关联。指挥人员可以基于实时证据判断火情，而不是只依靠口头汇报或单点告警。

### 3. 响应更快

火情识别后，系统可以把事件转入任务流，结合航线规划和无人机执行能力，快速形成复核、观察、跟踪或扑救任务。对森林火灾来说，响应速度直接决定能否把火情控制在小范围内。

### 4. 作业更安全

无人机可以进入浓烟、山地、沟谷、夜间或人员不宜进入的区域执行侦察和观察，减少消防人员暴露在高温、烟雾、落石、复杂地形中的风险。大载重无人机参与投放，也可以降低人员靠近火线的需求。

### 5. 指挥更直观

驾驶舱把直播、事件、任务和设备状态集中展示，适合指挥中心、应急值守室和现场指挥车使用。管理人员可以通过一个界面掌握“看得见的现场”和“可执行的任务”。

### 6. 落地更灵活

系统基于 DJI Cloud API、MSDK、ZLMediaKit、MQTT、WebRTC 等成熟技术路线扩展，既保留 Cloud SDK fallback，也推进 MSDK Agent 数据面。它可以根据不同地区的设备基础、网络条件和作业模式进行分阶段部署。

### 7. 可持续演进

系统已形成前端、后端、Android Agent、AI 服务、媒体服务和航线服务的模块化架构。后续可以继续增强模型效果、双模态识别、持久化任务队列、真机遥测校准、自动观测航线、FC100 灭火任务和多机协同调度。

## 六、典型应用场景

### 场景一：林区日常巡护

在重点防火期，系统可按预设航线对林区、景区、输电通道、祭祀点、农事活动区域和山地边界进行周期性巡查。无人机将实时画面回传驾驶舱，AI 服务持续识别火焰、烟雾或异常热源，值守人员可在平台中查看告警和截图。

适用价值：扩大巡护覆盖范围，降低人工巡山压力，提高火情早发现能力。

### 场景二：初期火情快速核查

当固定监控、群众上报、林区传感器或人工巡查发现疑似火情后，指挥人员可派无人机前往目标区域复核。无人机实时回传现场画面，系统记录火情位置、截图和风险等级，帮助确认是否需要启动扑救。

适用价值：减少误报带来的资源浪费，同时避免真实火点因确认慢而扩大。

### 场景三：复杂地形火场侦察

在山地、沟谷、林密区域，地面人员视野受限，消防车无法接近。无人机可以从空中观察火线走势、烟雾扩散、可通行道路、隔离带位置和周边风险点，为指挥员制定扑救路线提供依据。

适用价值：提升火场态势透明度，辅助指挥人员科学调度人员、车辆和无人机。

### 场景四：大载重无人机灭火投放

在火情处于初期或局部可控阶段时，侦察无人机负责定位火点和确认投放环境，FC100 等大载重无人机可携带灭火载荷前往目标区域执行投放。系统记录航线、飞行状态、投放前后影像和处置结果。

适用价值：让无人机从“看火”走向“参与灭火”，提高偏远区域早期处置能力。

### 场景五：夜间和低能见度巡查

夜间火情、阴燃热点和烟雾遮挡场景下，热成像和可见光结合可以增强发现能力。系统可以记录热源变化、异常区域和疑似火点，为夜间值守和次日复查提供依据。

适用价值：补足夜间人工巡查和普通可见光监控的短板。

### 场景六：灾后评估与复盘

火情处置结束后，系统可保留事件记录、识别截图、航线轨迹、任务进度、飞行状态和处置过程。管理部门可以基于真实数据复盘响应时间、任务调度、作业效果和装备表现。

适用价值：为战术优化、应急演练、责任追溯和装备采购评估提供证据。

### 场景七：应急演练和培训

系统可用于消防队伍、林业部门和无人机作业队伍的联合演练。通过模拟火情发现、无人机起飞、直播回传、火情识别、航线下发、任务执行和复盘总结，提升多部门协同能力。

适用价值：把抽象预案转化为可演练、可记录、可评估的数字化流程。

为避免视频脚本过度承诺，建议使用以下表述边界：

1. 可以重点宣传：实时直播、AI 火情识别、火情事件、驾驶舱态势、RC Plus Agent、航线任务、任务反馈、数据复盘、大载重灭火联动目标。
2. 对双可见光/热成像独立实时流，应表述为“双模态能力持续演进”或“支持可见光与热成像能力接入”，不要表述为当前已经稳定提供两路独立 raw stream。
3. 对 AI 模型效果，应表述为“可接入 YOLO 模型并支持现场数据持续优化”，不要承诺生产级准确率。
4. 对自动火点精确定位，应表述为“已形成多帧观测和精度演进设计”，不要直接承诺所有场景都已达到亚米级。
5. 对多机集群和 FC100 灭火，应表述为“系统面向大载重无人机灭火作业衔接和集群协同扩展”，根据实际演示素材决定是否说“已实飞验证”。
