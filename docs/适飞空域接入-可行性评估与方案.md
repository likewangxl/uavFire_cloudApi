## 1. 需求

系统当前的"哪里能飞"判定只能基于**系统自定义飞行区**。本需求要让判定**基于官方权威空域数据**(适飞 / 限飞 / 管控 / 禁飞),使规划阶段的合规提示有真实法规依据。

- 方向:接入官方权威空域数据。
- 产出策略:**先评估,可行再落地**。
- 数据源:由本文给出建议。

## 3. 核心可行性结论

1. **"直连官方 UOM 适飞空域接口"短期内不是工程问题,而是业务/合规问题。**
   民航局 UOM 的"适飞空域查询接口"**只对持 USS(航行服务提供方)资质的机构开放**,数据为 SM4 加密 JSON、非公开 GeoJSON。要拿到需先取得 UOM 运营合格 + USS 备案,或与持牌 USS 合作;周期数月,并附带"飞行动态实时上报 UOM(每 2–5 秒、12 类数据)"的强制义务。普通应用无法合法直拉。UOM 公众端(`uom.caac.gov.cn`,2026-05 已全国 34 省市上线全国适飞空域地图)是**给人看的地图,不是开放数据 API**。

2. **但"让判定基于真实区域"在工程上完全可行。**
   现有引擎 source-agnostic,只缺一个**空域数据源适配器 / 导入管道**:外部空域数据 → 归一化为 `NormalizedZone`(类别 + 圆/多边形 WGS84)→ 灌入 flight-area 库 → 现有渲染 / 判定 / 软确认链路即插即用(与禁飞区方案"官方区走离线导入"的既定结论一致)。

3. 据此把需求拆成两层:**近期工程可控(适配器 + 导入)** + **中期业务驱动(USS 正式通道)**。

## 4. 数据源对比与建议

| 方案 | 权威性 | 可获取性 | 合规 / 风险 | 工程量 | 评价 |
|---|---|---|---|---|---|
| **A. 离线导入**(政府公告 / 作业辖区实测 / 采购数据 → 现有库) | 中–高 | 高 | 低(自有数据) | 小 | **近期打底,推荐** |
| B. DJI FlySafe 限飞区(HTTP GeoJSON,全国,分 禁飞/授权区/高度限制/警示) | 中(DJI,非民航局) | 高 | 灰色(ToS 授权)+「限飞 ≠ 适飞」 | 小 | 仅作"与机端一致的限飞参考"补充,**勿当权威适飞** |
| C. 商用低空云平台采购(如星图低空云等) | 中–高 | 中(签约) | 中(合同) | 中 | 想"接近权威"又不自建 USS 时的现实选项 |
| D. 直连 UOM USS 接口 / 自建 USS | **最高(官方)** | 低(资质门槛) | 需资质 + 强制上报 | 大(业务级) | 中期正式通道,**非本期工程** |
| ✗ 逆向 UOM 公众地图矢量 | 高 | 不稳定 | 高(合规风险) | 中 | **不推荐** |

**建议**

- **短期**:以 **A(离线导入)+ 适配器抽象**打底;数据优先用可合法获取来源(作业辖区政府公告 / 实测,必要时 C 采购)。**B 仅作限飞参考补充**,商用前须法务确认 DJI 数据授权。
- **中期**:锁定一家**持牌 USS 合作**,作为权威实时数据 + 上报合规的正式通道;工程侧预留同一适配器契约对接,零返工。
- **不做**:自建 USS(过重)、逆向 UOM 公众地图(脆弱 + 合规风险)。

## 5. 推荐落地路径(分阶段)

- **P0 评估(本期 = 本文档)**:结论 / 数据源对比 / 分阶段设计 / 技术约束,供拍板。
- **P1 数据源适配器 + 导入管道(近期工程,待批后启动)**
  - 定义统一 `AirspaceSource` 归一化契约(输入任意来源 → 输出 `NormalizedZone[]`)。
  - 首个实现:**离线文件导入**(GeoJSON / shp)。可选第二个:DJI FlySafe 拉取器。
  - 归一化后经现有 `saveFlightArea` 或新增批量导入入库 → 现有渲染 + 判定 + 软确认**零改动复用**。
- **P2 USS 正式通道(中期,业务驱动)**:取得资质 / 合作后新增 `UssAirspaceSource` 实现同一契约,接入实时权威数据 + 飞行动态上报。

## 6. 关键技术约束 / 风险

1. **维度缺失:现有模型是 2D。** 适飞空域有高度上限(真高 ≤120 m,微型 ≤50 m),现有圆/多边形无高度字段。直接当 DFENCE 导入会**丢掉高度合规**。如需高度判定,要扩展 `flight-area.ts`(加 `maxAltitude`)+ 判定逻辑(增量工作)。
2. **数据量。** 全国适飞空域体量大,DFENCE"航线须全在内"规则若用全国数据会拖慢前端;灭火系统应**按作业辖区只导入相关区域**。
3. **类别映射。** 官方有 适飞 / 限飞(授权区·高度限制·警示)/ 管控 / 禁飞 多类,现仅 `NFZ`/`DFENCE` 两类。建议映射:禁飞、授权区 → `NFZ`(禁止);适飞 → `DFENCE`(须在内);高度限制 / 警示 → 新增"软告警"类(或暂归 `NFZ` 仅告警)。可能需给 `flight-area.ts` 加**来源 / 类别**字段以区分系统区与导入区。
4. **B(DJI FlySafe)双重坑。**「限飞 ≠ 适飞」语义不可混用;抓取 DJI 数据有 ToS / 授权灰色,商用前须法务确认。
5. **绘制 / 编辑 UI 仍停用**(MapLibre 迁移后 `use-mouse-tool` 为 no-op)。本需求只读不画,不受影响;若后续要手工增删区域,需另起一项用 MapLibre 重做绘制。

## 9. 实测验证(2026-06-26,本机 curl 实打 + 读码确认)

**方案 B(DJI FlySafe)= 现在就能用;数据源现成、免费、无需 key、已返回真实中国数据。**

- 接口:`GET https://www-api.dji.com/api/geo/areas`(实测 HTTP 200),参数 `drone / zones_mode=total / country=cn / level=0..8 / lng / lat / search_radius`(米,**空间查询**)。
- 机型列表:`GET https://flysafe-api.dji.com/dji/drones`(实测 200)—— 含本系统实际机队(DJI Mavic 3E/3T/3M = `industry-260`、Matrice 4T/4E、FlyCart 200),即拉到的限飞区与**本机队机端硬约束同源一致**。
- 返回结构:`areas[]`,每项 `area_id / name / type / level / color / lat / lng / radius` + `sub_areas[]`(圆 `shape=0` 带 `radius`;多边形 `shape=1` 带 `polygon_points`),坐标 **WGS84**,可直接映射现有圆/多边形模型(北京 50km 查询返回 13 个区:level 2×7 + level 3×6,含机场圆 + 石化厂区多边形)。
- **level → 现有类别映射**:2 Restricted / 4 Regulatory / 1 Authorization → `NFZ`(硬);0 Warning / 3 Enhanced Warning → 软告警;6 Altitude → 高度限制(2D 暂丢,软告警);7 Recommended / **8 Approved for Light UAV(仅中国,≈适飞)** → `DFENCE`。
- **工程约束**:① 接口有 CORS/CSP(`frame-ancestors *.dji.com`),**浏览器不能直连,必须走后端(本系统 Java 后端)代理拉取**;② 空间查询,覆盖辖区按作业点 `lng/lat+radius` 查即可,全国需网格扫;③ **非官方接口**(DJI 无 API 文档),需快照缓存、容忍结构变更;④ ToS/授权灰色,商用前须法务确认;⑤ 仍是"限飞区"语义(level 8 例外)。

**方案 A(离线导入)= 入库管道现成,但需自带权威数据。**

- 入库 API 已存在并确认:`saveFlightArea(body)`(`frontend/src/api/flight-area/index.ts:63`),`body = { id, name, type, content: { properties:{color,clampToGround}, geometry:{type,coordinates,radius?} } }`;逐区调用即可入库,批量端点为可选优化。
- 但**没有公开可下载的权威"适飞空域"文件**(UOM 适飞数据被 USS 闸住);A 的数据来源 = 政府禁飞通告数字化 / 实测 / 商用采购,即"容器就绪、米要自带"。

**结论**:A 与 B 共用同一条入库管道,区别只在"喂什么数据"。**当下唯一拿来即用的机读数据源是 B**;A 工程上随时可做但要你提供数据。建议 P1 起步先做 **B 的后端代理拉取器**(它天然也是 A 的导入器)。

## 10. P1 实现(2026-06-26 已落地)

把下载的**西安周边 100km** 限飞区(12 区 → 13 要素;`sub_areas` 多层逐层展开,与 DJI 官网画法一致;见 `data/airspace/`)灌入规划页,直接渲染 + 参与航线判定。**纯前端离线叠加,不写后端库、不下发机端**(飞机机端本就内置 DJI GEO,无需重复下发)。

- **数据资产**:`frontend/src/assets/airspace/dji_flysafe_xian.json`(= `data/airspace/dji_flysafe_xian.geojson` 副本,~7KB)。动态 `import()` 加载 → 构建时代码分割成独立懒加载 chunk,不进主包。刷新数据 = `python3 data/airspace/fetch-dji-flysafe.py`(西安中心+100km,自动展开 sub_areas)再 `cp` 到前端资产。
- **导入器**:`frontend/src/components/wayline-planner/airspace-import.mjs` 纯函数 `geojsonToZones()` —— GeoJSON → `NormalizedZone`;类别映射 `nfz→'nfz'(红,判定)`、`dfence→'dfence'(绿,判定)`、`warning/altitude→'warning'(琥珀,仅渲染不硬拦)`。配套 5 单测 `__tests__/airspace-import.test.mjs`。
- **接入点**:`use-flight-area-compliance.ts` 的 `loadFlightAreas()` 改为「系统区 + 离线导入区」合并进同一 `state.zones`(两路各自吞错互不阻断);渲染/判定链路零改自动接上。`use-planner-overlays.ts` 的 `FA_COLOR` 加 `warning→#faad14`。
- **验证**:`node --test` 新增 5 测全过、原 9 测不回归;`vite build` 通过,JSON 确认被分包;全量 45 测仅 5 个**存量无关失败**(FC100/驾驶舱/选择器,与本改动无关,stash 验证一致)。
- **判定语义**:5 个限飞(Restricted,红)= NFZ 硬判定(航点落入/航段穿越→软确认弹窗);8 个增强警示(琥珀)= 仅地图显示。**仍是 2D**,适飞空域高度维度未接(见 §6.1)。
- **范围决策**:本期只覆盖**西安市周边 100km**(作业辖区),非全国——数据量小、与作业区匹配、避免地图杂乱;换辖区改 `fetch-dji-flysafe.py` 的中心/半径重跑即可。
