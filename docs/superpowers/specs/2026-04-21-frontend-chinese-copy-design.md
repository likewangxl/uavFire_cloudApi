# 前端全量中文化设计

## 目标

将当前前端项目中用户可见的英文文案统一替换为中文，覆盖 Web 端与 Pilot 端常用页面、通用组件、按钮、表格列名、空态提示、弹窗提示、前端拼接的接口错误提示与关键调试日志。

## 范围

纳入本次中文化的内容：

- `frontend/src` 下用户界面中直接可见的英文文案
- `message.success / error / info / warning` 等提示文案
- 表格列标题、按钮文字、占位文案、标签、卡片标题、状态文本
- 直播页、工作台、驾驶舱、登录页、导航、设备页、任务页、图层页等页面中的界面英文
- 前端自行拼接的接口报错提示
- 控制台中在联调时会直接暴露给使用者的英文日志

不纳入本次中文化的内容：

- 后端返回的原始协议字段、枚举值、状态码、URL、路由名
- 前后端联调用到的英文参数名
- 内部变量名、类型名、函数名、文件名
- 第三方 SDK 或浏览器原生报错原文

## 设计原则

### 1. 直接替换，不引入国际化框架

本次目标是中文场景落地，不做中英文切换。所有前端可见英文直接替换成中文，避免引入额外架构复杂度。

### 2. 只改展示层，不改协议层

所有涉及接口契约、设备协议、路由枚举和内部状态机的英文标识保持不变。仅在展示时做中文映射或改写。

### 3. 保留必要行业缩写

对 `GPS`、`RTK`、`HUD`、`ASL`、`RTMP`、`GB28181`、`WebRTC` 等行业缩写不强制硬翻；若其外围文案为英文，则改为中文表达并保留缩写本身。

### 4. 优先修正“用户会看到”的英文

优先级从高到低：

1. 页面文案和交互按钮
2. 提示框、状态文案、空态文案
3. 直播/驾驶舱/工作台等当前高频页面
4. 调试日志

## 实施方式

### 1. 全仓字符串扫描

对 `frontend/src` 和必要的 `frontend/scripts` 做基线扫描，识别明显的用户可见英文字符串。按页面和组件归类，避免遗漏。

### 2. 分层替换

- 页面层：标题、说明、按钮、提示、表格列名
- 组件层：通用组件中的默认文案、直播组件、设备弹窗、任务面板等
- 接口提示层：前端自行拼接的英文错误文案
- 调试层：`console.log/info/warn/error` 中直接暴露的英文说明

### 3. 保守处理后端返回 message

若后端直接返回英文 `message`，本次不做全局机翻。只对前端本地生成的提示进行中文化；必要时在个别页面增加安全的中文包装提示。

## 验证

### 代码验证

- 增加回归脚本，检查关键页面和组件不再包含已知英文 UI 文案
- 对直播/驾驶舱相关页面保留已有回归测试

### 构建验证

- 运行 `npm --prefix frontend run build`
- 若出现仓库原有 Sass 警告或 chunk warning，可接受；新增编译错误不可接受

### 人工验证重点

- 登录页
- 顶部导航与侧边栏
- `leadership-cockpit`
- `livestream`
- `workspace`
- 设备、任务、图层、成员等后台页面
- Pilot 端首页与直播页

## 风险与规避

### 风险 1：误改协议字段导致联调失败

规避：不修改接口字段名、路由名、枚举值、URL、内部状态 key。

### 风险 2：遗漏散落英文

规避：先做全仓扫描，再分模块替换，最后复扫剩余高置信命中项。

### 风险 3：把行业缩写翻坏

规避：保留通用缩写，仅将其外围文案中文化。
