# TSA 通用弹窗皮肤设计

## 背景

当前 `frontend/src/pages/page-web/projects/tsa.vue` 中的弹窗样式主要依赖 Ant Design Vue 默认外观。

现状问题：

- 视觉上偏默认后台组件风格，和 TSA 页面当前的飞控 / 控制台氛围不一致。
- 不同类型弹窗缺少统一的视觉语言，确认、提示、状态反馈容易各写各的。
- 已经确认不能再使用阻塞主线程的原生 `window.confirm(...)`，因此后续弹窗应继续基于非阻塞的 Ant Design Vue Modal 能力实现。

本次目标不是引入新的弹窗组件体系，而是在保留 Ant Design Vue 原生 `Modal.confirm / info / warning / success / error` 调用方式的前提下，统一一套全局可复用的“通用弹窗皮肤”。

## 目标

- 为 TSA 页面建立一套统一的通用弹窗视觉皮肤。
- 保留现有 Ant Design Vue Modal 的调用模型，降低接入成本。
- 优先覆盖三类场景：
  - 确认类弹窗
  - 表单前后的提示类弹窗
  - 状态反馈类弹窗
- 视觉方向采用“浅色控制台”，而不是普通白底后台风。
- 动作按钮按语义分色：
  - 确认蓝
  - 成功绿
  - 警告橙
  - 错误红
  - 次级灰 / 描边

## 非目标

- 本次不引入新的弹窗底座组件，例如 `ControlModal`。
- 本次不重构全站弹窗调用链。
- 本次不尝试一次性替换项目里所有弹窗，只先为 TSA 页建立可复用样式方案并完成首个接入点。
- 本次不修改 Modal 的业务语义和现有确认 / 状态流程。

## 设计原则

### 1. 保持原生调用方式

继续使用 Ant Design Vue 原生静态方法：

- `Modal.confirm`
- `Modal.info`
- `Modal.warning`
- `Modal.success`
- `Modal.error`

这样可以避免为了样式统一去引入额外的包装层，保证改动范围可控。

### 2. 风格统一，但不脱离 TSA 页面语境

弹窗需要看起来像“控制台浮层”，而不是通用 SaaS 后台默认弹窗。视觉关键词：

- 浅色，不纯白
- 冷灰蓝底色
- 轻微头部渐层
- 边框清晰
- 阴影克制但有层次
- 信息块结构明确

### 3. 内容层级优先

弹窗美观的前提不是装饰，而是层级清楚。统一后的弹窗内容需要优先支持：

- 标题
- 辅助说明
- 结构化摘要
- 风险提示
- 操作区

### 4. 样式复用优先于单点特化

第一版不为“起飞确认”单独做专属视觉稿，而是输出一套可复用的通用皮肤。起飞确认只是首个接入场景。

## 视觉设计

## 整体基调

- Modal 外层为浅色控制台浮层。
- 主背景采用非常轻的冷灰蓝渐变。
- 标题区域增加弱蓝色顶部光感，用来替代默认纯色标题栏。
- 边框使用低饱和蓝灰色，不使用纯黑或纯白边线。

建议基础视觉参数：

- 圆角：`16px - 18px`
- 边框：`1px solid #d7e1ec`
- 主背景：`linear-gradient(180deg, #fcfdff 0%, #f4f7fb 100%)`
- 标题区背景：`linear-gradient(180deg, rgba(22,119,255,0.08), rgba(22,119,255,0))`
- 阴影：`0 22px 55px rgba(15, 23, 42, 0.16)`

## 布局结构

统一使用四段式结构：

1. 标题区
2. 正文区
3. 提示 / 风险区
4. 底部按钮区

其中：

- 标题区负责名称、设备上下文、弹窗类型。
- 正文区负责主说明、字段摘要、主要信息。
- 提示区用于警告、风险或成功 / 失败状态补充。
- 底部按钮区统一操作间距和主次按钮排序。

## 颜色语义

### 中性色

- 主标题：`#152334`
- 正文：`#344256`
- 次级文本：`#62748a`
- 标签文本：`#71839a`
- 边框：`#d7e1ec`
- 分隔线：`#dde5ef`

### 动作色

- 确认 / 主动作：蓝色 `#1677ff`
- 成功：绿色 `#1f9d55`
- 警告：橙色 `#f5a623`
- 错误：红色 `#e24a4a`
- 次级操作：灰描边 `#ccd7e3`

## 通用内容块

为了让原生 Modal 也能有统一观感，正文内容统一约定以下块级样式：

### 1. Summary Block

用于经纬度、高度、设备、状态等摘要信息。

表现形式：

- 浅色卡片
- `12px - 14px` 内边距
- 独立圆角
- 可双列，也可单列

### 2. Notice Block

用于普通说明。

表现形式：

- 蓝色左边线
- 浅蓝背景
- 正文颜色较深

### 3. Warning Block

用于高风险提示、自动切阶段提示、不可逆操作提示。

表现形式：

- 橙色左边线
- 浅橙背景
- 文字略强调

### 4. Status Block

用于成功 / 失败 / 处理中反馈。

表现形式：

- 按类型切换颜色
- 支持图标 + 简短结论 + 一句补充说明

## 交互规则

### 按钮区

- 默认右对齐。
- 次级按钮在左，主按钮在右。
- 所有按钮高度和圆角统一。
- 主按钮允许有轻微阴影，但不能过亮，避免廉价感。

### 标题和图标

- 确认 / 提示类允许弱图标化，但不强依赖图标。
- 第一版优先用颜色语义解决区分，不强制每类都引入复杂图标布局。

### 宽度策略

用户已明确偏好“中等宽度”。

建议：

- 默认宽度：`680px - 760px`
- 文本型确认：可偏窄
- 结构化确认 / 表单提示：使用默认中宽

## 技术方案

## 实现方式

不新建通用底座组件，采用以下方式统一皮肤：

1. 为 TSA 页内 Modal 调用统一指定 `className` 或 `wrapClassName`
2. 在 TSA 页或其关联样式文件中新增一组 Modal 覆盖样式
3. 对于内容结构化的弹窗，使用 `h(...)` 生成统一的内容 DOM 结构，而不是纯文本拼接

## 首批接入范围

第一批只做 TSA 页内直接可见、价值最高的弹窗：

1. 起飞确认弹窗
2. 返航确认弹窗
3. 降落确认弹窗
4. 关键状态提示弹窗（如成功 / 警告 / 错误）

其中起飞确认作为首个完整示例，验证：

- 非阻塞
- 结构化信息展示
- 样式统一

## 起飞确认弹窗结构示例

起飞确认建议改为以下信息结构：

### 标题区

- 主标题：`确认执行 DRC 爬升起飞`
- 副标题：设备名 + 当前 DRC 状态摘要

### 摘要区

- 当前位置
- 目标高度
- 第二阶段路径摘要

### 说明区

- 第一阶段动作说明
- 第二阶段动作说明

### 风险提示区

- 高度门槛达到后自动切第二阶段
- 不调用 `takeoff_to_point`

### 按钮区

- `取消`
- `开始起飞`

## 兼容性与风险

### 兼容性

- 不改变现有 Modal 非阻塞行为。
- 不改变现有业务提交逻辑。
- 不引入新的跨文件弹窗系统依赖。

### 风险

- 如果只覆盖局部样式而不统一内容结构，最终观感仍会不稳定。
- 如果不同类型弹窗各自写不同 DOM，样式复用度会下降。

因此第一版除了统一皮肤，还应同步给出一套“内容结构约定”。

## 实施步骤

1. 在 TSA 页确认类弹窗中统一加入皮肤 class。
2. 抽出起飞确认的结构化内容，替代长文本堆叠。
3. 为返航 / 降落确认复用相同结构与样式。
4. 为 `info / warning / success / error` 定义同一套浅色控制台皮肤。
5. 本地验证 TSA 页面视觉一致性和交互无回归。

## 验收标准

- 起飞确认不再使用默认 Ant Design 样式。
- 弹窗整体风格与 TSA 页面一致，明确呈现“浅色控制台”而非普通后台弹窗。
- 不再出现单纯长文本堆叠的确认内容。
- 不影响现有非阻塞行为。
- 同类弹窗在标题区、正文区、提示区、按钮区具备统一样式。
