# 无人机火情智巡微信小程序——实施计划与验收

## 1. 计划基线

### 1.1 目标

按照“只读移动驾驶舱 → 业务闭环 → 报告通知 → 持久化指令 → 受控飞行操作 → 真机灰度”的顺序交付，避免小程序 UI 先于安全底座上线。

### 1.2 估算假设

建议团队配置：

- 产品/交互 1 人。
- 小程序前端 1–2 人。
- Java 后端 2 人。
- 测试 1 人。
- 运维/安全 0.5 人。
- 多机型飞手/设备工程师按适配与验收阶段投入；至少覆盖遥控器链路和 Dock 链路。

在外部资质、域名、首批机型设备和测试环境按时到位的前提下，平台核心建议周期 **14–18 周**，
约 **150–205 人日**。单人顺序实施不建议承诺日历工期，预计至少 30 周，
并且设备验收仍需要飞手和测试人员独立参与。

该估算只覆盖平台核心和首批代表性组合；每新增一个飞机/控制端/负载/固件组合，
需单独评估适配、回归和飞行窗口，不能把“所有机型”作为 18 周内无条件完成项。

估算不包含：正式 UOM/USS 对接、电子签章采购、短信/语音供应商采购、FC100 远程释放、全新 AI 模型训练。

### 1.3 分支策略

当前开发从 M300 适配工作树分出，但交付范围为多机型能力驱动平台。原工作树已有未提交的航线区域、地图轨迹和 Agent 改动，开始编码前应先由改动所有者完成提交或拆分，随后：

```text
feature/m300-model-adaptation
  -> codex/m300-miniapp-foundation
  -> codex/m300-miniapp-report-notification
  -> codex/m300-miniapp-flight-command
  -> codex/m300-miniapp-live
```

每个阶段使用独立 worktree，避免污染主目录或覆盖当前未提交工作。数据库采用向前兼容的扩展式迁移，不在功能分支删除现有字段。

## 3. 工作分解

## 3.1 阶段 0：方案评审与项目准备

周期：1 周，8–12 人日。

### 阶段 0 工作项

- `P0-01` 评审产品范围、角色、权限和首版禁用能力。
- `P0-02` 确认小程序主体、名称、Logo、隐私政策和服务类目。
- `P0-03` 申请业务域名、WSS 域名、媒体域名、证书、备案和 WAF。
- `P0-04` 申请订阅消息模板及 `live-player` 能力，记录审核前置条件。
- `P0-05` 建立首批兼容矩阵，明确 M3E/M3T/M3M、M30/M30T、
  M300/M350、M3D/M3TD、M4E/M4T 及计划接入的 M4D/M4TD、M400
  所对应控制端、载荷、固件和 SDK 路径。
- `P0-05A` 为每个组合指定真实设备、飞手、验收窗口、能力等级和证据负责人；不具备设备的组合标记为目标范围，不标记为已支持。
- `P0-06` 建立 dev/staging/pilot/prod 环境和测试 workspace。
- `P0-07` 评审本文 API，冻结 v1 字段、状态和错误码。
- `P0-08` 明确报告模板、签阅法律/内部管理属性和保留期限。

### 阶段 0 出口条件

- 业务负责人、安全负责人、飞行负责人和技术负责人完成评审。
- 未决事项有负责人、截止时间和降级方案。
- 飞行控制总开关默认 `false`。

## 3.2 阶段 1：后端基础与微信身份

### 阶段 1 后端

- `BE-01` 新建 `miniapp` 模块包和 `/miniapp/api/v1` Controller 边界。
- `BE-02` 建立统一响应、错误码、requestId、参数校验和异常映射。
- `BE-03` 实现微信 `code2Session` 客户端、超时、重试和熔断。
- `BE-04` 创建 `miniapp_user_binding`、`miniapp_session` 迁移及 Repository。
- `BE-05` 实现登录、绑定、管理员审核、refresh token 轮换和注销。
- `BE-06` 增加角色/权限/数据范围检查，修复任何客户端 workspace 信任路径。
- `BE-07` 实现审计拦截器，敏感字段脱敏。
- `BE-08` 接入速率限制、feature flag 和客户端最低版本控制。

### 阶段 1 小程序

- `MP-01` 初始化工程、环境配置、代码规范、API SDK 和类型生成。
- `MP-02` 实现登录、绑定、待审核、禁用和工作空间切换页面。
- `MP-03` 实现 access token 刷新单飞机制，防止并发刷新风暴。
- `MP-04` 实现权限指令、统一错误、空态、数据延迟和强制升级页面。

### 阶段 1 测试

- code 一次性使用、微信 API 超时、绑定冲突、禁用账号。
- refresh token 轮换、重放撤销、跨设备注销。
- 跨 workspace、越权对象 ID、管理员无飞行权限。
- 日志扫描确保无密码、AppSecret、session_key、JWT、refresh token 和完整 OpenID。

### 阶段 1 出口条件

- 认证与授权单元/集成测试通过。
- 安全评审确认会话、加密、日志和数据范围设计。
- 小程序开发版可完成真实微信登录及测试账号绑定。

## 3.3 阶段 2：只读移动驾驶舱

周期：2 周，22–30 人日。

### 阶段 2 后端

- `BE-10` 实现首页 summary 聚合和 partial/warnings 语义。
- `BE-11` 实现任务列表、详情、时间线、航迹和媒体聚合。
- `BE-12` 实现火情/AI事件列表、详情、证据和坐标转换。
- `BE-13` 实现设备战备摘要、遥测新鲜度和 HMS 摘要。
- `BE-14` 建立 GCJ-02 转换服务并保存转换版本。
- `BE-15` 增加短缓存和领域事件主动失效。

### 阶段 2 小程序

- `MP-10` 今日态势首页。
- `MP-11` 任务列表、筛选、详情、时间线。
- `MP-12` 航线/实际航迹地图，设备、事件和风险图层。
- `MP-13` 火情/异常列表、证据查看、位置精度和更新时间。
- `MP-14` 设备详情、载荷、电量、RTK、HMS 和可出动状态。
- `MP-15` 图片预览、弱网重试和缓存清理。

### 阶段 2 测试

- BFF 指标与 PC 驾驶舱同一测试数据下结果一致。
- 设备状态超过阈值后由在线变为 DELAYED/STALE。
- WGS84/GCJ-02 转换在标准点位误差满足地图显示要求。
- `(0,0)`、无定位解、过期 OSD 不绘制为有效位置。
- 子服务失败时首页显示部分异常，不把失败解释为 0。

### 阶段 2 出口条件

- 领导用户完成 30 秒态势识别可用性验收。
- 只读功能可独立上线，飞行控制继续关闭。

## 3.4 阶段 3：实时事件

周期：1–1.5 周，12–18 人日。

- `BE-20` 实现一次性 WSS ticket 和权限绑定。
- `BE-21` 建立关键事件存储/游标补拉；定义高频遥测最新值策略。
- `BE-22` 接入任务、命令、事件、问题、报告和设备状态事件。

## 3.8 阶段 7：持久化飞行指令安全底座

周期：3 周，32–44 人日。该阶段是小程序飞行操作的硬前置。

### 阶段 7 数据与服务

- `BE-60` 创建 `flight_command`、command event、outbox 和审计迁移。
- `BE-61` 用数据库队列替换 `pendingByDrone`，兼容旧 Agent poll/ACK 契约。
- `BE-62` 实现每飞机串行、优先级、领取锁、租约、过期和重试。
- `BE-63` 实现幂等键、请求哈希、任务乐观锁和互斥矩阵。
- `BE-64` 实现 Agent ACK 与 MSDK 最终事件关联、超时和未知结果处理。
- `BE-65` 建立命令状态投影、时间线、实时事件和监控指标。
- `BE-66` 实现全局/workspace/用户/机型/设备/动作灰度开关。

### 阶段 7 预检与确认

- `BE-67` 实现动作权限和任务状态规则。
- `BE-68` 校验 Agent/飞机/遥控器在线、数据新鲜度和控制权。
- `BE-69` 校验规范机型族、控制端/机场、载荷型号与位置、运行时能力、航线契约、验收矩阵版本和逐动作开关。
- `BE-70` 接入电量、RTK、GNSS、HMS、天气/空域留证和时间窗。
- `BE-71` 签发一次性 confirmToken，绑定完整风险快照。

### 阶段 7 验证

- 服务在命令排队、派发、ACK、执行每个节点重启，指令不丢不重。
- 同时提交 100 次相同幂等键，只产生一个命令。
- 同一幂等键不同请求体返回冲突。
- 同一飞机互斥命令严格串行；STOP 不静默覆盖 EXECUTE。
- 任务/设备/载荷在预检后变化，旧 confirmToken 失效。
- Agent ACK 后失败，小程序不得显示成功。

### 阶段 7 出口条件

- 移除生产路径对内存单槽命令的依赖。
- 故障注入、并发和重启恢复测试全部通过。
- 小程序端仍只连接模拟指令，真实动作总开关保持关闭。

## 3.11 阶段 10：系统联调与安全测试

出口条件：P0/P1 缺陷关闭，P2 有书面接受；安全高危/严重问题为 0。

## 3.12 阶段 11：多机型设备与飞行验收

代码测试不能替代本阶段。

### G0 模拟环境

- 模拟 Agent 延迟、掉线、重复 ACK、乱序状态、失败和超时。
- 验证小程序不出现状态倒退、重复执行或假成功。

### G1 真机地面通电

- 按兼容矩阵逐行核对飞机、遥控器或 Dock、载荷、固件、Agent/APK 或 Cloud 适配器及后端提交身份。
- 验证心跳、OSD/HMS、载荷位置、遥测新鲜度和指令拉取。
- 不装桨/按现场安全规程隔离动力，验证任务准备和拒绝条件。

### G2 低风险受控测试

- 在批准的封闭场地按飞行负责人方案执行。
- 依次验证执行、暂停、恢复、停止；每次只开放一个动作。
- 验证遥控器接管、链路丢失、低电量和 RTK 变化。

### G3 航线飞行

- 固定白名单账号、飞机 SN、控制端、载荷、兼容矩阵版本和航线。
- 验证航点、航迹、进度、媒体、完成返航、报告与通知。
- 记录每个指令的 API、数据库、Agent、MSDK 和现场视频证据。

### G4 火情链路

- 保持所有未通过 L6 专项验收的火情闭环默认关闭，先按具体机型与载荷验证被动检测和事件上报。

## 6. CI/CD 门禁

每个合并请求至少执行：

1. `git diff --check`。
2. Java 格式/静态分析、目标模块单元和集成测试。
3. 小程序 lint、typecheck、unit、组件测试和构建。
4. OpenAPI YAML 语法、引用解析和 breaking-change 检查。
5. 数据库迁移在空库和上一版本快照上各执行一次。
6. 依赖漏洞、密钥和敏感日志扫描。
7. 状态机、错误码和 API 文档一致性检查。

进入 pilot/prod 还需要：

- 产物版本、Git 提交和 SHA-256 固化。
- 配置差异和 feature flag 审批。
- 数据库备份和恢复验证。
- 监控、告警、值班和回滚负责人确认。
- 设备/飞行验收证据与批准记录。

## 7. 发布与回滚

### 7.1 发布顺序

```text
备份与迁移演练
  -> 部署向后兼容数据库结构
  -> 部署后端但 miniapp.enabled=false
  -> 运行冒烟和只读检查
  -> 发布小程序体验版
  -> 开启只读白名单
  -> 开启报告/通知/督办
  -> 开启模拟飞行指令
  -> 指定用户+飞机+动作的 pilot 灰度
```

### 7.2 回滚原则

- 优先关闭 feature flag，不先回滚数据库。
- 数据库迁移采用 expand/contract；当前版本只 expand，旧代码应忽略新表/列。
- 飞行控制异常立即关闭 `miniapp.flight-control.enabled`，保留只读和审计查询。
- 通知异常暂停 Worker，不删除待发送记录。
- 报告异常暂停生成，不影响任务终态和既有报告下载。
- 媒体异常关闭直播入口，保留快照和遥测。

### 7.3 回滚触发条件

- 任一重复飞行指令、状态假成功或跨 workspace 数据暴露。
- 登录/刷新导致大量用户不可用且 15 分钟内不能恢复。
- P95 首页延迟连续 15 分钟超过 3 秒或错误率超过 2%。
- 通知重复发送率超过 0.1% 或高等级事件未创建通知任务。
- 报告哈希、版本或签阅对应关系异常。

## 8. 风险登记

| 风险 | 概率/影响 | 应对 |
| --- | --- | --- |
| 微信类目或直播权限未获批 | 中/高 | 首版快照+遥测，直播独立成 P1，不阻塞只读 MVP |
| 订阅消息授权不足 | 高/中 | 站内待办为底座，关键事件增加短信/电话可选通道 |
| Agent 单槽命令丢失/覆盖 | 当前存在/严重 | M3 前完成数据库队列，飞行控制此前保持关闭 |
| 不同机型的媒体、UXSDK 或 Dock 资源冲突 | 中/高 | 按控制链路真机专项验证，明确原生飞行页与后台推流优先级 |
| 机型/控制端/载荷身份误判 | 中/严重 | SN、规范型号、控制端、载荷位置和固件联合匹配，fail-closed |
| 非 M300 被默认映射为 M4T 拓扑 | 当前存在/严重 | 建立显式适配器注册表；未知组合禁止发布或控制 |
| 枚举存在但未真机验收 | 高/严重 | API 标记证据等级，仅 VERIFIED 可控制 |
| 弱网导致重复操作 | 高/严重 | 幂等键、confirmToken、版本锁、结果恢复 |
| 报告事实被后续数据修改 | 中/高 | 不可变快照、版本和哈希 |
| 公网暴露内网控制面 | 中/严重 | Gateway/WAF、网络隔离、媒体分域、最小接口 |
| 领导误触高风险操作 | 中/严重 | 默认无控制权、操作分级、二次确认、飞手确认 |
| 项目范围过大拖慢首版 | 高/中 | 先只读和报告，直播/直接返航/P2 智能能力后置 |

### 9.2 每周检查

- 已完成项必须附代码、测试或外部申请证据。
- 风险清单更新概率、影响、负责人和计划日期。
- 单独报告代码完成、自动化测试、环境部署、设备验证和实飞验收，不合并成一个“完成”。
- API/状态机变更先改文档和契约，再改客户端与服务端。

## 10. Definition of Done

一个功能只有同时满足以下条件才算完成：

- 产品验收标准和异常场景明确。
- API、状态机、权限、错误码和审计已实现并同步文档。
- 单元、集成、契约和 E2E 测试通过。
- 监控、告警、日志脱敏和 feature flag 已配置。
- 数据库迁移、备份、回滚或关闭策略已演练。
- 安全检查无未接受的高危/严重问题。
- 涉及设备时完成真机验证；涉及飞行时完成批准场地的实飞验收。
- 产物身份、提交、配置和验收证据可追溯。

## 11. 首批开发任务建议

建议第一个迭代只领取以下任务：

1. 建立 `/miniapp/api/v1` 骨架、统一响应和错误码。
2. 完成微信登录、用户绑定、会话轮换和 RBAC。
3. 完成首页 summary、任务列表/详情、事件列表/详情的只读 BFF。
4. 初始化小程序并实现登录、首页、任务和事件四条只读路径。
5. 建立 OpenAPI 契约校验、测试 workspace 和 feature flag。

这个迭代不改 Agent、不开放飞行控制、不接直播，能够最快形成可评审、可演示、风险可控的首个版本。
