## 2. 核心结论

小程序定位为“领导移动驾驶舱”，不是遥控器替代品。首版围绕以下闭环建设：

```text
微信登录与组织绑定
  -> 今日态势与待办
  -> 巡检任务和实时进度
  -> AI 异常/火情确认
  -> 审批、批示、派单和督办
  -> 自动生成巡检报告
  -> 微信订阅消息送达
  -> 复检、签阅和归档
```

复杂航线规划继续由 PC 端承担。小程序只浏览已发布航线、完成审批，并对已通过安全预检的任务发起受控操作。

## 3. 现有能力与新增范围

### 3.1 直接复用

- `planned_wayline` 航线计划、KMZ 生成、发布、准备和任务状态。
- RC Plus Agent 的航线下载、执行、暂停、恢复、停止、进度和事件回传。
- MSDK 设备状态、OSD/HMS、可见光直播和 ZLMediaKit 播放链路。
- 火情事件、AI 识别证据、坐标质量、空间合并、事件处置和任务编排。
- PC 领导驾驶舱已有的指标定义、地图态势和在线设备口径。
- FC100 合规留证、资源分配、任务状态机和派发前预检。

### 3.2 新增能力

- 微信身份登录、系统账号绑定和组织权限映射。
- 面向移动端的聚合 API（Mini Program BFF）。
- 领导审批、批示、督办、复检和签阅闭环。
- 通用巡检问题单和整改状态机。
- 巡检报告模板、异步生成、版本、签阅和归档。
- 微信订阅消息授权、发送、失败重试和送达审计。
- 持久化飞行指令队列、幂等、二次确认、回执和超时闭环。
- 统一审计日志、移动端风险控制和可观测指标。

### 3.3 上线前置项

1. 将 `WaylineAgentServiceImpl.pendingByDrone` 的内存单槽命令升级为持久化队列，禁止新命令静默覆盖未完成命令。
2. 完成 M300 + 指定载荷 + 第一代 DJI RC Plus 的真机、实载荷、实飞航线验收。
3. 保持 `m300FireClosedLoopEnabled=false`，直至专项验收通过并完成受控灰度。
4. 配置可从微信公网访问的 HTTPS/WSS 域名、证书、API 网关和媒体出口；不得暴露内网管理接口。
5. 完成微信小程序主体、服务类目、订阅消息模板和 `live-player` 权限审核。
6. 高风险操作必须完成 RBAC、二次确认、幂等、操作原因、审计和飞手现场确认。

## 4. 事实源与边界

- 当前生产能力和现场证据以 `../CURRENT_PROJECT_STATUS_2026-08-05.md`、仓库根目录 `RUNBOOK.md`、当前代码及专项验收记录为准。
- 本文档描述目标方案，不代表对应代码已经实现、部署或通过设备/飞行验收。
- 小程序不得绕过 DJI Pilot 2、飞手、官方安全限制或正式空域审批系统。
- AI 只提供发现、风险排序和辅助摘要，不自动批准起飞、投放、返航或归档真实事件。

## 5. 版本管理

- 文档、OpenAPI 和实现代码必须使用相同版本号。
- API 破坏性变化通过 `/miniapp/api/v2` 发布，不在 v1 原地改变语义。
- 文档修改必须同步维护 `openapi.yaml`、错误码表、状态机和验收用例。
- 每次现场验收单独形成记录，明确设备 SN、机型、载荷、Agent/APK、后端提交、测试环境和结论。
