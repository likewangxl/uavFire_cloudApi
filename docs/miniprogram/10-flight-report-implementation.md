# 自动刷新、官方设备名称与飞行报告实施记录

日期：2026-09-16。状态：软件、数据库与服务器更新已验证；遥控器安装及实飞验收待现场进行。

## 验收目标

1. 首页删除手动刷新按钮；可见且登录时每 5 秒刷新，离开/后台停止，单请求在途，失败保留最近数据并提示数据时间。
2. 小程序按 Apple HIG 的浅色分组列表、系统字级、蓝色操作、44 点触控目标和安全边距调整；在浏览器检查所有页面及窄屏状态。
3. 使用单一设备名称目录，展示、API 名称和数据库名称采用 DJI 官方完整拼写。SDK 枚举、标识符、序列号及原始审计载荷通过兼容层保留含义，不做破坏协议的文字替换。历史名称迁移先备份，再事务更新及独立回读。
4. 任务详情提供可追溯的飞行报告：任务/设备、计划与实测区分、实际飞行起降证据、时长、速度、高度、电量、轨迹/航点、执行事件、火情及媒体关联、数据缺失与时间间隙。
5. 新任务事件与遥测持久化；完整记录分页，不以最新状态或 500 条内存缓存冒充全程。历史未采集字段显示“未记录”，不根据计划参数伪造实测值。

## 已核实的边界

- 现有 `WaylineEventStore` 是每任务最多 500 条的内存缓存；进度仅覆盖当前任务状态，没有完整遥测历史。
- `WaylineProgressDTO` 已提供速度、相对高度、坐标、电量；MSDK 状态有实时速度、高度、电量等。起飞与落地必须使用飞行状态证据，航线完成不能等同落地。
- 现有库只有任务、任务状态、火情历史、媒体等表，无全程遥测表。发现一条陈旧执行中记录，未提供最近进度时间。
- 服务器：小程序独立服务 8090，既有火情后端服务 6790；6789 属另一运行进程，更新时需保持目标隔离。

- 统一官方名称目录、兼容解析、MyBatis 名称写入/读取类型处理器、UI 标签守卫，以及仓库后续命名规则。SDK 枚举、SN、协议路由、CSS 类名和原始审计载荷保留技术含义。
- 数据库已备份并迁移 **81 个名称单元格**，13 个名称字段扩展至 256 字符，保留默认值、排序规则及注释；逐单元格回读一致。再次扫描无剩余待迁移名称。备份位于工作区上级 `.codex-temp/device-name-backups/`。
- 新增 `flight_report_run` 和 `flight_report_record`。记录任务执行快照、执行事件、遥测与接收时间，按工作空间隔离、去重、稳定分页；采集失败独立回滚，不中断现有飞行控制流程。
- 起降以飞行状态采样为证据；返航电量取返航模式采样；电量消耗为百分点。超过 15 秒间隙不插补速度/轨迹，多次起降或电量跳变不输出误导性的单次消耗。计划修改不会覆盖已保存的执行快照。
- 小程序与 PC 任务详情均可查看概览、起降电量、计划、记录完整性、时间线、候选关联火情、媒体及全部记录。坐标保留原始数值精度，垂直速度为 NED 向下为正。旧 SDK 相对高度不会冒充绝对高度。

## 使用与现场边界

- 本地浏览器检查：`miniprogram` 下运行 `npm run preview`，本次地址为 `http://127.0.0.1:61723/`。
- PC 组件检查：Vite 下 `/preview/flight-report.html`，使用独立合成数据，不发送生产请求；不进入生产默认构建入口。
- 真机界面需重新编译并使用新预览码。当前数据库历史遥测为 0 条，历史缺失数据无法补采或反推。
- 此次没有连接任何 USB/ADB 遥控器，**没有安装 APK 或进行实飞验收**。Agent 项目原有构建配置仍指向旧网络 `192.168.0.100`，本次 Debug APK 仅作编译验证；现场安装前必须使用实际遥控器配置、当前服务器地址和原有认证配置打包，不能直接把该检查包当作现场已部署版本。
- 当前持久化报告覆盖规划巡检任务的 Agent/MSDK 事件。DJI FlyCart 100 独立投放任务的完整飞行遥测尚需其官方数据接口提供，不能把当前巡检报告宣称为所有运输任务的实飞报告。
- 火情是同设备、同记录时段的候选关联，媒体仅为执行编号匹配的元数据；没有冒充已确认归属、媒体预览、签阅或正式 PDF。
