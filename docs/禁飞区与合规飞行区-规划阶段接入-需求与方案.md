# 禁飞区 / 合规飞行区 —— 规划阶段接入（需求与方案）

> 状态：需求已明确、现状已调研、方案待定稿（**3 个范围决策待拍板**，见文末）。尚未动代码。
> 记录时间：2026-06-22

## 1. 需求

系统需接入**禁飞区管理**与**合规飞行区域管理**：哪里可以飞、需要系统判断；并且**在规划航线阶段**进行提示，可能的话**自动绕行禁飞区**。

## 2. 现状调研（关键结论：底子已有，缺的是"规划期判定"）

本系统基于 DJI cloud-api-sample，**已内置一整套"飞行区（flight-area）"基础设施**，本需求是在其之上接入规划页，而非从零开发。

**已具备：**
- **数据模型**（`frontend/src/types/flight-area.ts`）
  - `EFlightAreaType.NFZ`（`'nfz'`）= 禁飞区 / GEO Zone
  - `EFlightAreaType.DFENCE`（`'dfence'`）= 合规作业区 / Task Area（"可以飞"的区域）
  - 几何：**圆**（中心 + 半径）或**多边形**；坐标 **WGS84**（与规划页天地图同坐标系，判定**无需坐标转换**）
- **后端 API**（`frontend/src/api/flight-area/index.ts`，前缀 `/map/api/v1/workspaces/{ws}`）
  - `getFlightAreaList` / `saveFlightArea` / `deleteFlightArea` / `changeFlightAreaStatus`
  - `syncFlightArea(device_sn[])`（下发到飞机，机端硬约束）/ `getDeviceStatus`（同步状态）
  - 数据库：`device_flightarea`、`flightarea_file`、`flightarea_property` 等表；cloud-sdk 有 `com.dji.sdk.cloudapi.flightarea.*`
- **机端同步 + 飞行中告警**：飞行区可下发到飞机；飞行中通过 WS `FlightAreasDroneLocation`（到边界距离 / 是否在区内）实时告警。

**缺口（本需求要补的）：**
- **规划阶段完全不感知飞行区** —— 布点 / 拖点 / 生成航线时不判定、不提示、不绕行。
- 附带问题：飞行区的**绘制管理 UI 在地图迁移到 MapLibre 后被临时停用**（`use-mouse-tool` 守护 no-op）。但"**读取已有飞行区做规划判定**"不依赖绘制，可独立先做；若需新建区域，需用 MapLibre 重做绘制交互（单独一项）。

## 3. 方案（分阶段）

### P0 数据接入与渲染
- 规划页拉取 `getFlightAreaList()`，用 MapLibre GeoJSON 在地图上渲染：NFZ（红）/ DFENCE（绿）。
- WGS84 直接用，工程量小。

### P1 规划期判定 + 提示（核心）
- 几何判定（新增纯函数模块 ~40 行：点在圆内 = haversine ≤ 半径；点在多边形内 = 射线法；线段穿越 = 线段相交）：
  - 航点**落在 NFZ 内** / 航段**穿越 NFZ** → 违规；
  - 若已定义 **DFENCE**，航线必须**全部落在 DFENCE 内**，否则违规（与 DJI 机端约束一致）。
- UI：违规航点 / 航段**高亮** + 工具栏**告警条**（如"航点 3 在禁飞区内""航线超出作业区"）；**保存 / 下发**时按所选拦截强度处理。

### P2 自动绕行（"可能的话"）
- 对穿越 NFZ 的航段：给 NFZ 加 buffer，用绕边 / 可见图算法插入绕行航点。
- 明显更复杂，建议 P1 判定+提示稳定后再做。

### 合规模型（拟定，待确认）
- **NFZ = 禁止**：航点不可落入、航段不可穿越。
- **DFENCE = 边界**：若存在 DFENCE，则航线必须**完全在其内**；不存在则不约束"必须在内"。

## 4. 待拍板的范围决策（下次开工先确认）

1. **数据源**
   - (A) 仅系统自定义飞行区（已接入，工程量小、闭环可控）—— 推荐先做
   - (B) 额外接入 DJI 官方 GEO/限飞区数据库（需 DJI GEO 接口或离线库，工程量大 + 数据授权问题）
2. **本期范围**
   - (A) 判定 + 提示（渲染 + 高亮 + 告警 + 保存/下发拦截）—— 推荐先做
   - (B) 判定 + 提示 + 自动绕行（含 P2）
3. **拦截强度**
   - (A) 编辑时仅告警，**下发执行硬拦截** —— 推荐
   - (B) 仅告警不拦截
   - (C) 保存即拦截（最严，编辑中间态会频繁被挡）
