# 20 机视频分级上传开发方案

日期：2026-09-05。基线：main / ab6471d。关联：[网络评估](video-network-and-multi-aircraft-deployment-2026-09-05.md)。

## 已确认需求

20 架飞机保持视频上传，正常运行时最多 4 路高清、其余 16 路低清；不使用全机高清，也不以无人观看停传作为本期常态。高清目标 1920×1080 / 4,000,000 bit/s；低清目标 960×540 / 500,000 bit/s。两档采用 MSDK 输出编码设置，不改相机镜头、图传分辨率或本地 ONNX 输入链。

原始视频预算 24 Mbps，按 25% 开销及 70% 持续利用率规划，需约 43 Mbps 可用共享上行，另计其他业务。该预算以源端设置真正生效为前提；压缩纹理、关键帧和重传会产生波动。现有飞机图传、无线盲区及客户端算力不能由码率调度消除。

## 本期架构与边界

保留 RTMP → ZLM → WebRTC。新增专用的视频策略轮询，与飞行/激光命令队列隔离。业务后端是一个带宽域的唯一调度实例；本期支持单实例后端、一个明确登记且不超过 20 架的机群。多活后端、SRT 回传、转码副本和 20 宫格新界面列入后续扩展，不作为本期已实现能力。

所有新版 Agent 默认低清启动。只有持有后台有效短期授权的飞机可以高清。后台关闭分配、接口不可用、认证失败或授权超时都回低清；降档只操作推流编码，不解绑本地取帧。本期不做视频无人观看停流，因此无需先完成整体停止生命周期解耦。

## 高清调度与一致性

1. 高清上限为 4，机群名单由部署配置明确登记。高清授权最长 15 秒，Agent 每 2 秒独立轮询；本地 250 ms 看门狗使用单调时钟检查过期，网络超时不能阻塞看门狗。
2. 排序：已验证火情的临时优先级 > 用户正在查看的飞机 > 配置的重点飞机 > 已有高清飞机 > SN 稳定顺序。候选仅包含近期报告、协议兼容且实际起流的 Agent。超过四个同级需求时排队，不扩容高清上限。
3. 换人时停止续租旧飞机，但旧授权到期后再保留 10 秒设备降档保护期，在此期间继续占用名额；不因浏览器离开、心跳过期或收到一个低清报告立即释放。新飞机等待空位，从而避免切换瞬间超过四路。
4. 后端重启后等待最长授权及 10 秒设备保护期（合计 25 秒）再发高清，防止旧租约仍生效时重复授权。此机制不支持两个调度实例同时发租约；部署验收必须确认单实例。
5. Agent 按请求发出前的单调时间计算本地到期点，扣除请求耗时；丢弃过期、协议不匹配或身份变化后的结果，后台时钟回拨不延长本地租约。续租不重复写 SDK，档位变化才应用。
6. 相同 SN 的并行 Agent 实例视为冲突，停止发新高清授权并报告原因；批量 APK 不写固定飞机 SN。

## 接口与数据

- `POST /manage/api/v1/dual-stream/agents/{sn}/video-policy`：复用 Agent token、HTTPS 策略及 timestamp/nonce 校验；设备身份绑定路径。请求报告协议版本、进程 instanceId、已应用档位、起流状态、SDK 观察值及故障；响应返回协议、目标档位、码率、授权时长、原因、租约标识。具体字段以代码及测试为准。
- `POST /manage/api/v1/video-bandwidth/viewers/{viewerId}`：登录用户续租当前重点飞机，单个页面独立 viewerId；不提交 SN 表示释放。用户必须有该设备所属工作区权限。观看租约过期自动清理，多位用户合并需求。
- `GET /manage/api/v1/video-bandwidth/status`：返回该用户工作区内已登记设备的调度及实测状态，区分目标、已应用、观察值及更新时间。不同工作区不暴露彼此设备详情。

前端既有驾驶舱选机/离开页面同步观看租约，并显示高清/低清/等待原因。状态指标增加浏览器接收码率、解码帧率、丢包和新帧停滞；统计采样及页面销毁需清理，后台页停止续租。浏览器统计不标为端到端延迟。

## 设备端实现约束

- 设置 `MANUAL` 后按 bit/s 应用两档码率，显式关闭音频，防止 SDK 默认策略破坏总预算。
- 推流 start/stop/档位更新串行化。切镜头的既有重启必须保留当前有效档位，租约失效后不得重新以旧高清起流。
- 质量设置失败时不报告已应用；先恢复低清，无法恢复则停止网络推流并报告故障，保留本地帧消费者。不能通过整体 session stop 降档。
- 实际输出码率优先使用 MSDK status listener；配置 getter 与实际发送观测分开，读不到不能填零冒充正常。实际码率是否稳定在目标附近需真机及 ZLM 入站测量。
- 不改动火情证据先上传后确认的鉴权链、不启用未验收飞控、不调整 ONNX 模型或机型门禁。

## 发布与验收

后端调度默认关闭，未配置机群不给高清；新版 Agent 始终低清起步。先升级地面单机验证两档、取帧和切镜头，然后配置 4 机、20 机逐步放行。旧 Agent 不受新策略控制，必须全部升级并核对 APK/进程身份后才能宣称 4+16 已覆盖机群。

自动化验收包括：20 并发申请不超过 4 租约、优先级/过期/重启/同 SN 冲突、跨设备/跨工作区拒绝、网络挂起不延长高清、迟到响应、档位失败与低清回退、SDK 档位变化不解绑 AI、浏览器计数器复位与订阅清理。

现场验收另记录 20 路真实发送码率、至少 30 分钟延迟趋势、丢包/限速下冻结情况、高清交接最大等待、本地识别输入尺寸和帧龄。参考目标 LAN 稳态 P95 ≤ 800 ms、正常公网 P95 ≤ 1.5 s，需以真实空地图传基线修订。未达到现场条件时，软件可以交付测试版，但不能标为部署验收通过。
