# 分级视频上传实施计划

日期：2026-09-05。用户选定 20 路持续上传、最多 4 高清＋16 低清。设计见 [开发方案](video-bandwidth-development-design.md)。

| 阶段 | 交付项 | 验收出口 |
| --- | --- | --- |
| 1 方案与分支 | 新建 codex/video-bandwidth-4hd-16sd；设计、任务、评审记录 | 名额交接、过期降档、权限、本地 AI、部署边界无未处理的设计阻断项 |
| 2 后端 | 机群配置、租约调度、身份绑定策略接口、观看优先级、可观测状态 | 并发/时间/隔离行为测试通过；无全量升高清或重启超发 |
| 3 Agent | 低清启动、手动码率、独立轮询、单调时钟看门狗、SDK 状态 | 单元测试及实际 SDK 编译通过；网络异常不会无限维持高清 |
| 4 前端与部署 | 现有驾驶舱观看需求、档位状态、播放统计；部署配置和操作步骤 | 前端专项和构建；配置对应实际 RTC 端口；不声称已实现多宫格 |
| 5 集成复审 | 复查异常路径、协议序列化、后台重启、SDK 并发、已有飞控边界 | 修复新增问题，汇总测试证据和待现场事项 |
| 6 地面及现场 | 1 → 4 → 20 机；真实上行及多观众验证 | 两档真实生效、全部 Agent 已升级、单调度实例、带宽/延迟/AI 同时达标 |

本轮授权范围包含分支内开发和自动验证；没有可用的现场参数/设备时，不对真实服务器或飞机进行推测性部署。默认低清和关闭高清分配是发布过渡状态；正常配置与稳定授权后形成 4+16，名额交接期间允许少于四路高清。

按顺序实施，阶段间不省略评审；有问题先修正方案再写代码。源码与自动测试完成不替代第 6 阶段。关闭后台高清分配后，等待租约过期观察全机回低清，是本期回退方式，不直接回退到旧版全高清 APK。

## 当前完成情况与执行顺序

阶段 1–5 已完成分支内实现、复审及上述自动验证；阶段 6 尚未执行。详细证据见 [评审记录](video-bandwidth-design-review.md)。

地面单机先验证低清起流，启用该机高清后从 ZLM 入站确认码率/分辨率；再切镜头、停后端和阻断策略接口，核对本地到期降档及 ONNX 输入连续性。通过后扩为 4 台，再扩为 20 台；每一批核对实际安装版本、SN 和进程，而不是仅核对构建目录。

20 机阶段分别验证稳态四高清、同时争用、火情优先、观看者离开、同 SN 实例冲突、重启及网络丢包。每组记录实际流量、峰值、高清交接等待、视频 P50/P95/最大延迟和冻结时长；至少连续运行 30 分钟。媒体入口/出口和客户端解码负载分开统计，多观众共用服务器源，不增加同一飞机的发布副本。

网络部署阶段先确认单机和共享链路的实测容量，再配置现场可管理网关的队列和预算：给指令、心跳及事件元数据保留资源，视频与证据上传分别控制；本轮不对未知现场路由器套用通用命令。容量不足或媒体地址不可达时停止放量，保留 LOW，修复后重测。

预计现场节奏为单机半天、4 机半天、20 机及多观众一天，另留问题修复与复测时间；这是设备和网络已齐备后的排期估算，不是通过承诺。正式发布须闭合 SDK 真机、全机升级、网络容量及既有前端失败的验收记录。
